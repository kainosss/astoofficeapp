# ASTO Office

Private business management and quotation application for **ASTO SECURITY** (Brisbane, QLD).
Built for Cloudflare Workers + D1, protected by Cloudflare Access. Intended production address: `https://office.astosec.com` (not yet deployed).

## What it does (MVP)

- **Quotation builder**: customer → installation address → CCTV package or blank → edit equipment, costs, quantities, labour, travel, markup and overheads → live profitability → scope/inclusions/exclusions/terms → customer preview → save → A4 PDF.
- **Quotations**: numbered `ASTO-Q-0001`…, statuses (Draft, Sent, Accepted, Declined, Expired), duplication, and **revisions**. Marking a quote as *sent* locks that revision and snapshots business details, customer details, prices, GST treatment and terms. Later changes create a new revision; issued revisions are never overwritten.
- **Customers** with multiple installation sites, search (name, phone, email, address, suburb, postcode).
- **Equipment catalogue** with supplier, SKU, ex/inc-GST purchase prices, pack quantities (e.g. 305 m cable boxes costed per metre), default or per-item markup, optional fixed sell price, estimate flag, active flag.
- **CCTV packages** (ASTO Home CCTV 6MP $2,790 / 4K $2,990), with fixed or calculated pricing. Kit components (cameras, NVR, HDD) are listed as *included in kit* with zero cost, so nothing is double-counted.
- **Dashboard** from real data, **Settings** (logo, ABN, contact details, rates, GST, validity, terms, thresholds) and **exports** (full JSON backup, customer/quote/equipment CSV).

## Quick start (local)

Requires Node 20+.

```bash
npm install
npm run db:reset:local     # create local D1, apply migrations, load seed data
npm run dev                # builds the client and starts wrangler dev on http://localhost:8787
```

Open <http://localhost:8787>. Locally you are signed in as `dev@localhost` (development bypass — see Security).

For front-end work with hot reload, run `npx wrangler dev` in one terminal and `npm run dev:ui` in another, then open <http://localhost:5173>.

## Pricing model

All money is integer cents; percentages are basis points; quantities/hours are hundredths. Rounding is half away from zero, applied per line.

- **Cost basis.** While *not* GST-registered (current setting), GST paid to suppliers can't be claimed, so **GST-inclusive** purchase prices are the cost and **no GST is charged** to customers. If GST registration is switched on, GST-exclusive costs are used (input tax credits assumed claimable on eligible purchases) and GST is added to customer prices.
- **Selling price.** *Calculated*: each line = cost × (1 + markup) (or a fixed sell price), plus consumables with markup, labour (hours × complexity × rate) and travel. *Fixed package*: package price + items marked as extras + labour above the package's included hours + travel.
- **Price override.** You can set the final total payable. Internal costs are unchanged, and the customer sees a "Discount"/"Price adjustment" line so the breakdown still adds up.
- **Profitability (internal only).** Direct costs (equipment, materials, consumables, travel cost) → gross profit → minus overhead and warranty allowances (% of price) = **contribution** (before owner labour and personal tax) → minus **notional owner labour** (hours × a management rate, not a wage or deduction) = **surplus**. Gross margin, markup and contribution margin are shown, with warnings below the configured thresholds.

Overhead %, warranty %, notional owner labour rate and warning thresholds are **starting assumptions** in Settings — review them.

## Internal vs customer-facing data

Previews and PDFs are built only from a whitelisted `CustomerQuote` object (`getCustomerQuote` in `src/worker/services/quotes.ts`). It contains no supplier costs, SKUs, suppliers, markup, overheads, allowances or profitability. Tests check both the JSON and the PDF text for leaks.

- Customers are fictional (`example.com` emails, ACMA-reserved fictional phone numbers).
- ABN, phone, email, deposit, payment and warranty terms are **placeholders** — set them in Settings. Nothing has been invented.

## Security

- **Production authentication**: Cloudflare Access in front of `office.astosec.com`, **and** the Worker verifies every API request's Access JWT (`Cf-Access-Jwt-Assertion` header or `CF_Authorization` cookie) with `jose`: RS256 signature against the team's JWKS (`/cdn-cgi/access/certs`), issuer = team domain, audience = Access application AUD tag, expiry, and an explicit **admin email allowlist** (`ADMIN_EMAILS`). Unverified headers such as `Cf-Access-Authenticated-User-Email` are never trusted.
- **Fails closed**: missing/placeholder Access settings, an empty allowlist or an unknown `AUTH_MODE` → HTTP 500 with no data.
- **Development bypass** (`AUTH_MODE=dev-bypass`) is refused whenever `ENVIRONMENT=production`, and only works for requests to `localhost`/`127.0.0.1` — even if the dev configuration were deployed by mistake.
- Strict security headers (CSP, `X-Frame-Options`, `nosniff`, HSTS, `Referrer-Policy`, `Permissions-Policy`), `Cache-Control: no-store` on API responses, cross-origin write rejection, zod validation with numeric bounds, parameterised SQL, CSV formula-injection neutralisation, `noindex` robots.

## Deployment checklist (requires approval — nothing has been deployed)

1. `npx wrangler d1 create asto-office-db-prod`, then put its id in `wrangler.jsonc` → `env.production.d1_databases`.
2. In Cloudflare Zero Trust, create a **self-hosted Access application** for `office.astosec.com` with a policy allowing only your email(s). Copy the team domain and **AUD tag** into `env.production.vars` (`ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`) and set `ADMIN_EMAILS`.
3. `npx wrangler d1 migrations apply asto-office-db-prod --remote --env production`
4. `npm run build && npx wrangler deploy --env production` (adds the `office.astosec.com` custom domain; does not touch `astosec.com`).
5. Enter real business details and terms in Settings. Do **not** load the development seed into production.
6. Confirm an unauthenticated request to `https://office.astosec.com/api/me` is blocked.

Production backups: `npx wrangler d1 export asto-office-db-prod --remote --env production --output backup.sql`, plus D1 Time Travel, plus the in-app JSON export.
